The dump itself is not in this repository.

## Shape

The file is not comma-separated CSV. Every record is one line with six fields
split on U+203D INTERROBANG (`‽`):

| column | notes |
|---|---|
| website | source site name, never empty |
| url | absolute page URL, never empty |
| title | free text |
| tags | comma-separated labels, case-sensitive, not normalized |
| upload_date | mostly `DD/MM/YYYY`, often blank |
| video_id | site-local id, never empty in this dump |

- 23,686,411 data rows, plus one header line.
- 0 malformed rows: every line decoded as UTF-8 and had exactly six fields.
- Scan time on this machine: 850.5 s, about 7.3 MiB/s.

Reading that table:

- **XVideos and Eporner contribute every missing upload date.** Their date column is entirely blank (10,603,562 of the 10,603,594 blanks). The other 32 blanks are XHamster.
- **PornHub is the only source of unparseable dates** (286 rows). Every other site is clean on the dates it actually stores.
- **XHamster tags are much denser** (mean 20.8 per row, and no empty tag field) and its titles run the longest (max 904).
- **DrTuber is the most regular**: one empty title, no empty tags, no missing dates, and both URL length and title length are tightly bounded (every URL is 25 characters).
- Empty titles are concentrated on Eporner (17,270 of 18,311). Empty tag fields are concentrated on XVideos (140,466 of 166,885).

So a global "44.8% of dates are missing" is the wrong summary to act on. Dates are complete for DrTuber, PornHub, and XHamster, and absent for XVideos and Eporner.

## Tags

Tags are not a controlled vocabulary. The same idea is stored under several
strings (`amateur` 4,578,478 and `Amateur` 1,929,576; `blowjob` and
`Blowjob`; `teen` / `Teen` / `teens`). Any downstream count should
lowercase and fold separators (`big-tits`, `big tits`, `Big Tits`) before
ranking. The top raw strings are dominated by amateur, blowjob, hardcore,
HD, teen, cumshot, and anal.

A large tail of rare tags (2.1 million distinct strings, while a row averages
only ~13 tags) means many labels occur once. Treat rare tags as noise unless
they are normalized.
